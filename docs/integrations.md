# Integration setup

Credentials belong in `.dev.vars` locally or server runtime secrets in production. They are never stored in the browser or returned by the configuration endpoint. The Integrations screen displays only whether the required server values are present; it does not claim a credential has been tested.

## Linear (primary)

1. Create a personal API key with access to the intended team.
2. Set `LINEAR_API_KEY` and `LINEAR_TEAM_ID` (the team UUID).
3. Resolve team members’ Linear user UUIDs, and set an exact speaker mapping:

```json
{ "Sarah Chen": "linear-user-uuid", "James Wilson": "linear-user-uuid" }
```

Set that JSON string as `LINEAR_ASSIGNEES`. Review the owner in Trace before publishing. The server checks every approved task before creating any issues, passes `assigneeId` explicitly, and checks both HTTP and GraphQL errors. Personal keys are sent directly in the Authorization header as required by Linear. OAuth access tokens may be configured with a `Bearer ` prefix in the secret value.

Every issue includes the description, owner, optional agreed deadline, timestamp links, source quotations and a stable `trace:` marker. High/Medium/Low map to Linear priorities 2/3/4.

## GitHub

Set `GITHUB_TOKEN` to a fine-grained token with Issues write access to the target repository. Set `GITHUB_REPOSITORY=owner/repository` and `GITHUB_ASSIGNEES` to a JSON mapping of exact speaker names to GitHub logins. The assignee must be assignable in that repository. Trace verifies the created issue response includes the requested assignee; an unexpected result is held as uncertain for reconciliation. GitHub has no native issue deadline field, so the agreed date is included in the issue body.

Choosing both Linear and GitHub intentionally creates one issue in each destination. Choose only your team’s tracker if you want one task overall.

## Slack

Create a Slack app, enable Incoming Webhooks, authorize the intended channel, and set `SLACK_WEBHOOK_URL`. Trace accepts HTTPS `hooks.slack.com/services/…` URLs. Each reviewed meeting gets one summary containing accepted decisions, approved tasks, owners and evidence links. Meeting text uses plain text blocks. Output titles and owners escape Slack control characters, and evidence links are generated by the server. Transcript text cannot introduce broadcast-mention syntax. Incoming webhooks do not return a message permalink, so the ledger records delivery without an invented URL.

## Notion

Set `NOTION_API_KEY` and `NOTION_PARENT_PAGE_ID`. Share that page with the integration. Each accepted decision becomes a child page with the complete ADR Markdown, evidence URLs and a Trace marker. Long text is split into bounded paragraph blocks. This reference exports Markdown as page text; it does not convert every Markdown construct to native Notion formatting.

## MeetStream

Set `MEETSTREAM_API_KEY`. Import using **the transcript ID**, not the bot ID. Trace calls:

```text
GET /api/v1/transcript/{transcript_id}/get_transcript?raw=false
Authorization: Token <server secret>
```

A 202 response means processing is incomplete and is shown as a retryable message. No empty meeting is created. You can also upload the speaker-labelled JSON directly:

```json
{
  "transcript": [
    {
      "speaker": "Sarah Chen",
      "start_time": 12.5,
      "end_time": 21.8,
      "transcript": "We decided to use cursor pagination."
    }
  ]
}
```

Times are seconds from the meeting start. Transcript evidence links open the correct turn in Trace. Raw media playback is not included.

## Claude

Set `ANTHROPIC_API_KEY`, and optionally `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`, verified against the current model catalogue at implementation). Transcript content is sent to Anthropic only when the Claude checkbox is enabled. The response must pass the same runtime contract as imported data. Approval and completion flags from AI are overridden to false, and extra model fields cannot change meeting identity. Invalid or truncated responses are shown as errors; switching off Claude uses deterministic rules.

Without a key, rules extract explicit “we decided/agreed” statements and first-person commitments. They do not infer implicit consensus, rich tradeoffs, third-party assignments or deadlines. Read and correct every draft before accepting it.
